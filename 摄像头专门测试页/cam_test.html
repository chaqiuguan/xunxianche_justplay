📹 摄像头实时测试

延迟模式:

🐢 高延迟模式 — HLS

原理ffmpeg 将 RTSP 流切成 2 秒一段的 .ts 文件 → Python HTTP 服务 → 浏览器 hls.js 播放
延迟5 ~ 15 秒（视频攒够一个分段 + 网络传输 + 浏览器缓冲）
优点稳定性高、有缓冲抗抖动、兼容所有浏览器、数据量小
适用网络不稳定时、不需要实时操作的场景（如任务复盘查看）
数据流RTSP → ffmpeg → .ts 文件 → HTTP GET → hls.js → <video>

🚀 低延迟模式 — HTTP-FLV

原理ffmpeg 持续输出 FLV 流 → 浏览器 mpegts.js 通过 MSE 实时解码到 <video>
延迟1 ~ 3 秒（仅网络传输 + 少量缓冲）
优点延迟低、实时性好、画面即时反馈
缺点网络波动可能导致画面卡顿或花屏、数据量稍大
适用需要实时监控、操控车辆时使用
数据流RTSP → ffmpeg → FLV → HTTP 长连接 → mpegts.js → MSE → <video>
